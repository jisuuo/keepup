# ADR-001: 기술 스택 선택 (Java 21 / Spring Boot / MySQL 8.4)

- 상태: 채택
- 날짜: 2026-10-10
- 관련 주차: 1

## 상황
- 목표는 커머스·핀테크·플랫폼 회사 이직용으로, 실사용자가 있는 서비스를 하루 1시간씩 26주 운영하는 것이다.
- 질문 체크리스트(Q1~Q5)가 다루는 **스레드 풀·커넥션 풀·락·인덱스·동시성**을 눈으로 볼 수 있는 스택이어야 한다.
- 돈 흐름(원장·정산·환급)을 다루므로 **트랜잭션과 행 잠금**이 확실한 RDBMS가 필요하다.
- 혼자 운영하므로 로컬 개발과 배포가 단순해야 한다.

## 대안
| 대안 | 장점 | 단점 |
|---|---|---|
| **Java 21 + Spring Boot + MySQL** | 톰캣 스레드 풀(200)·HikariCP(10) 기본값을 그대로 관찰 가능, 트랜잭션·락 학습 자료 많음 | 보일러플레이트가 많고 기동이 느림 |
| Kotlin + Spring Boot | 같은 런타임, 코드 간결 | 언어 학습이 병행되어 Q1~Q5 공부 시간을 잠식 |
| Node.js(NestJS) + PostgreSQL | 빠른 개발 | 단일 스레드 이벤트 루프라 Q2의 스레드 풀 관찰 대상이 달라짐 |
| Java + PostgreSQL | MVCC·락 문서가 좋음 | 아래 이유로 MySQL을 택함 |

## 선택
- 언어·런타임: Java 21 (Gradle 툴체인으로 고정)
- 프레임워크: Spring Boot (web, data-jpa, actuator)
- DB: MySQL 8.4, 로컬은 Docker Compose
- 빌드·실행: Gradle Wrapper, 로컬 DB는 `compose.yaml`

## 이유
1. 영상 기준의 질문(Q2·Q3·Q4)을 **기본 설정 그대로** 재현할 수 있다. 예: 톰캣 기본 스레드 200, HikariCP 기본 풀 10.
2. MySQL 8의 `SELECT … FOR UPDATE SKIP LOCKED`로 웹훅 워커(23주)와 선착순 홀드(15주)를 구현할 수 있고, InnoDB의 B+Tree 인덱스와 갭 락은 17주 인덱스 실험의 직접 대상이다.
3. 개인 사정: Java와 Spring은 써 본 적이 있지만 깊게 파는 것은 이번이 처음이다. 어느 정도 익숙해서 언어·프레임워크 학습량이 줄고, 그만큼 Q1~Q5 공부에 시간을 쓸 수 있을 것이라고 기대한다(기대일 뿐 아직 검증하지 않았다).

## 트레이드오프와 다시 볼 시점
- 가정: 이 스택이 목표 회사군에서 흔하다는 점은 아직 직접 확인하지 않았다. 현재 공고를 찾아보는 중이며, 확인되면 이 문서에 결과를 적는다.
- PostgreSQL이나 Kotlin이 더 나았을지는 이번 프로젝트에서 비교하지 않는다. 비교는 26주 정리 때 한 줄 회고로 남긴다.
- 단일 DB·단일 서버로 시작하므로 읽기 분리나 샤딩은 범위 밖이다. 21주차 이후 지표가 필요하다고 말해 주면 그때 다시 본다.
